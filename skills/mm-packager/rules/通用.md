> 格式：做法（原因）〔日期〕。只写当前有效版本，改过程记 CHANGELOG.md。用户当次要求优先于本文件。
> 版式专属见 rules/B-剧情选择.md、rules/C-网感剪辑.md；地区专属见 rules/JP.md；目录、timeline、出片、自检见 rules/工程交付.md；可选套路见 library/打法.md。

## 投放原则

- 审美和投放冲突时按投放做：先保证看得懂、看得清、想去玩，再谈简约和融入（包装是买量素材，目标是转化）〔2026-10-30〕
- 核心玩法尽早出现，开头标题、铺垫、无台词段都要压缩（买量素材前几秒就决定观众划不划走）〔2026-10-30〕

## 文案来源与补充

- 屏幕文字 = 全量文案 + 包装补充文案，其他字一律不上屏（文案只有两个出处，可追溯）〔2026-11-10〕
- 全量文案（$P/全量文案.md）只读，剧本已写的分幕、台词、选项、数值名/触发点/幅度照用，包装不改（剧本出核心剧情，包装只补全）〔2026-11-10〕
- 剧本给什么、包装补什么见 SKILL.md「分工」；全量文案已写的直接用，不另写（用户裁决）〔2026-11-10〕
- 补充文案出片前列成一张清单给用户（外语附中文，并注明每句用在哪个位置），用户确认后才做；用户要改的只改补充清单，不回写全量文案（补充文案也只有一个出处）〔2026-11-10〕
- 口播：全量文案写了就直接用；没写就直接读 `$SK/../shortdrama-copy/references/投放高效文案.md`，按地区→性向取，用户指定了要传达的意思就按用户的；不搬、不复制那份文件（口播库只维护一份）〔2026-11-10〕
- 第一句台词前出现的字都算标题（标题、开场字、钩子说明字），台词/口播字幕和选项界面的「目标」不算；标题不是必须的，要加由包装补写并随补充清单确认；用户说去掉标题就全部去掉，开头只放 Logo；用户说去掉某类元素时按同类全去，汇报时写清删完还剩什么（只删了标题、留着开场字，用户：『标题去掉』『我让你删掉开头标题，你聋了吗』）〔2026-11-10/11-12〕
- 用户口头给的中文（卡名、简介、聊天数等）先改成目标语言的地道说法，附中文进补充清单确认（「聊天数 100万」照搬上屏被否）〔2026-11-02〕
- 去标点在包装渲染时做：屏幕文字去掉句号、逗号（句中的换成空格或换行），保留 ？！；不回写全量文案（句号逗号不表达情绪，还影响排版）〔2026-10-22〕。各语言额外保留的符号见 rules/<地区>.md
- 没有人声的段落不加字幕、不编台词；ASR 只用来取时间，文字以全量文案为准；原声或画面（道具、服装）和文案对不上时不改字，写进补充文案「需要拍板」交用户定，多版本每个版本都查（ASR 会幻听、认错同音字和品牌名，例如把 MiraiMind 听成 未来マインド；病娇女教师选项「白衣を掴む」，v1 没穿白大褂、v3 是护士服）〔日期待补/2026-11-12〕

## 字幕与文字

- 口播必须配逐句字幕，逐句字幕必须有底板（半透明圆角底+描边），不能和背景糊在一起（五音梗口播字幕和背景糊在一起被指出）〔2026-11-09〕。C 的口播关键句大字不算逐句字幕，样式见 rules/C-网感剪辑.md
- 字幕和气泡按逐字/逐词时间出字，自做字幕的句首用能量起点校正；整句一次出现算不合格（ASR 句首常偏早）〔2026-10-20〕
- 重点文字用大字号、粗体、强对比（描边/投影/底板任选），尺寸宁大勿小；不用 Medium 及以下字重（细字在手机上看不清）〔2026-11-02〕
- 字放不下就换行或拆句，不缩字；只有产品 UI 卡片名可以自动缩字号（缩字就看不清，卡片名要照产品界面）〔2026-11-02〕
- 对话气泡、输入框字号 64–76（1080×1920），B、C 都适用；app-ui 产品气泡 56 号例外，照产品界面（手机上 50 号看不清）〔2026-11-02〕
- 所有文字和 UI 都不挡角色的脸：先抽帧看脸的位置，标题一般放在脸下方（画面 65–80% 高处），放不下就下移或换行（原因待补）〔2026-10-20〕
- POV 片子有手入镜时，字幕和 UI 避开手的区域（手会把字挡住）〔2026-10-26〕
- 带抖动/缩放的大字按最大位移算安全边界，任何一帧都不能出画（原因待补）〔2026-11-04〕
- POV 主角的内心独白不做成对话气泡：不加框，用手写感字体和（ ）包住，分段逐块浮现（淡入+轻微上浮），画面加暗角/压暗（要一眼看出是心里话）〔2026-10-21〕
- 热度数字（聊天数、人数）B、C 都可以用，出现时持续往上跳；数字由包装补写并进补充清单确认，写法按目标语言习惯，具体见 rules/<地区>.md〔2026-11-04/05〕
- 不用粉色综艺字幕（用户：廉价）〔2026-10-21〕

## 画面与 UI

- 任何时刻底层都要有画面：源视频里模型生成的渐黑/黑场段切掉，定格帧不能是黑帧（投放平台和观众都会把黑屏当成坏片）〔2026-10-21〕
- 全片一套配色、字体、UI 语言，后加的手机屏、目标、片尾也用同一套（不统一被要求返工）〔2026-10-21〕
- 不给所有 UI 都加玻璃框/气泡框（用户：『气泡太丑』）〔2026-10-21〕
- 同一位置同一时刻只出现一个 UI，前一个完全退场下一个才出现（用户：『3·2·1 叠在一起』）〔2026-10-22〕
- 贴着人物的元素（跟脸框、跟随字幕、指向角色的标记）用检测/跟踪定位，生成前先出『原帧+元素位置』核对图自己看过（位置不准比不做更糟，用户否决过手标坐标）〔2026-10-20〕
- 对定格帧做缩放时，蒙版和跟脸坐标同步变换（不同步元素会脱离角色）〔2026-10-27〕
- 开头不能只做位移/淡入，要有逐帧特效（冲击波、色散、闪白、震屏、粒子、速度线、扫光、推镜任选）（用户：『纯位移动画太廉价』）〔2026-10-21〕
- 开头放 MiraiMind Logo（图标+字标）；品牌名一律用 Logo 字标图，不用字体手打 MIRAIMIND（原因待补）〔2026-10-21/27〕
- 开头不放剧情说明卡（用户删过，拖慢开头）；标题只在开头出现（弹入→停留→淡出），不能和进度条、台词、画面重点同时抢视线〔2026-10-20/21〕
- 画面里的时间、数字、名字要和台词/剧情对得上；片尾背景帧要和剧情结局一致，用结局状态那一帧（原因待补）〔2026-10-20/22〕
- 包装图层全部自己生成，不套旧模板素材（旧模板路线已不再参考）〔日期待补〕
- 用户说『重新设计/不合格/太丑』就整套重做，不在原参数上小修（原因待补）〔日期待补〕
- 用户给了参考代码/页面，先抓原文件按原写法 1:1 移植，不只学大意（用户：『我都给你参考代码了还做不对』）〔2026-10-22〕
- 用户指定只参考某工程的某一部分时，就只参考那部分，其余按本片剧情设计（女骑士整套照搬签售会被否）〔2026-11-05〕

## 动画节奏

- 所有 UI 都要有入场动画，不能一帧突然出现（用户：『识别框出现要有动画』）〔2026-10-20〕
- 每次画面切换（片头→正片、选项点完、进片尾），每条信息至少停 0.8–1 s（用户：『节奏太快』『根本反应不过来』）〔2026-10-22〕
- 画面静止 ≥ 1.5 s 的段（定格、产品 UI 详情页）加慢推（静止画面显得死，病娇女教师复审指出详情页静止）〔2026-11-12〕

## 产品 UI 承接与片尾

- 正片切到产品 UI 必须有承接转场，不能硬切（用户评价硬切『生硬』）〔2026-11-09〕
- 承接转场默认做法（B、C 都用）：剧情最后一镜定格（可轻度去饱和），约 0.6 s 缓入缓出缩进手机屏（白边圆角 + 投影），背景用本片帧模糊叠品牌渐变，手机屏内再交叉淡入 app-ui 划卡/聊天（女骑士、上の階、签售会都这样做并验收）〔2026-11-04/05〕。备选做法见 library/打法.md
- 剧情后的承接段照产品真实 UI（Figma 设计稿）做，画面风格照商店页；没有参考就先向用户要，要不到且用户同意时才用试玩广告 UI 备选（观众点进商店看到的要和视频里一样）〔2026-10-30〕。参考位置见 reference/投放参考/README.md
- 剧情后的软件功能展示首选 modules/app-ui；产品 UI 可以精简，但按钮的形状、颜色、文字必须和产品一致（用户：『按钮相关的都必须和产品大差不大』）〔2026-11-02〕
- UI 上的按钮/标签文字用该地区产品原文，KR/EN 向用户要截图，不自己翻译（要和产品界面一致）〔2026-11-02〕
- 划卡：前面划走的陪衬卡用 library/cards.md 里往期已上线 B/C 素材的卡，旧版片的角色卡不当陪衬卡；最后停住的 hero 用本片角色（旧版片已不作参考）〔2026-11-10〕
- 每张卡必须有名字和简介，标签按需；卡面库或全量文案里缺的由包装补写，进补充清单给用户确认；文字不出界（缺字段的卡看着像假的，毒舌講座迭代二争一卡因没文案被打回）〔2026-11-10〕
- 自己做的片尾：片中帧做底，从上到下是 Logo → 文案 → 下载按钮 → 两个一样大的商店标，有聊天数就显示；字体、配色、UI 延续正片，不用通用贴字/按钮（和正片无关的片尾被打回）〔2026-10-20/22〕
- 自做片尾元素依次出现，约每 0.5 s 一个；手指连点约 4 下、间隔约 0.3 s，点完就结束；进片尾前加过渡（闪白/倒带等）；背景亮度按题材定；总长 ≤ 10 s（留够反应时间又不拖）〔2026-10-22〕。JP 尾板模块不受这条限制，见 rules/JP.md

## 声音

**来源**
- 音效来源：① 用户音效收集 `$USER_SFX`（取值顺序见 reference/环境.md）→ ② 没有再用 ElevenLabs 生成；`$RES/sfx` 里的 g26/lgx/liquid/kpop/s_glitch 是本地合成的，不用（`qa.py tl` 查到 timeline 引用它们会报错）；不自己合成（用户：『音效太雷霆了，让你用我找好的或者用 elevenlabs 生为什么不做』）〔2026-11-12〕
- BGM 必须用 ElevenLabs music 为本片新生成，不复用往期 BGM，不用曲库或本地合成（用户裁决）〔2026-11-10〕。JP 尾板例外见 rules/JP.md
- 口播照全量文案或补充清单里确认的口播，用 voice skill（ElevenLabs）生成；atrim 去掉首尾静音，节奏太慢才加 atempo，限 1.05–1.15（原因待补）〔2026-11-05〕。音色在定方案时让用户选，见 SKILL.md

**BGM**
- 剧情段和承接+尾板段各生成一首，交界处淡出淡入；正片 BGM 在片尾起点前 0.5 s 淡出；黑幕/转场后 BGM 不能断（原因待补）〔2026-11-05〕
- ElevenLabs BGM 生成后先量包络：开头静音、中途断档、某段提前结束的部分都不用，只排有声段，断了按小节续接（病娇女教师三种都中了，复审才发现）〔2026-11-12〕
- BGM 必须是纯音乐，demucs 测人声 < -45 dB（往期 BGM 带人声被骂过）〔2026-11-05〕
- BGM prompt 写出高级感/drama 感，贴合地区和情绪，关键重音对齐画面动作（用户：『音乐廉价』『BGM 太垃圾』）〔2026-10-22〕

**音效**
- ElevenLabs 音效和 BGM 的提示词统一带避开项：雷声、轰鸣、boom、sub bass、低频冲击、爆炸、清脆叮咚（tink）、沙沙、八音盒；生成后量低频，偏重就高通：UI 短音 300 Hz 双级高通，心跳 70 Hz 高通 + 120 Hz 轻提，BGM 80 Hz 高通 + 150 Hz lowshelf −8 dB 出 `_lite`（用户都否决过：『太雷霆』、八音盒叮叮当当）〔2026-11-10/11-12〕
- 不加思考音效（用户裁决）〔2026-11-10〕
- 丝滑音效（柔和 whoosh/swell，起止淡入淡出、没有硬瞬态）只用于微恐题材（用户裁决）〔2026-11-10〕
- 音效太小声用 volume+alimiter 提（加 alimiter 防爆音）〔2026-10-21〕
- 消音哔要柔和、不刺耳，音量贴着原声，被打码的原声同时压低（用户：『哔声吓人』）〔2026-10-22〕

**混音与闪避**
- 人声清楚优先，BGM 也要听得到；不靠整体压低原声来让 BGM 显出来；原声里混有音乐/环境声时先用 Demucs 分离人声再提亮（用户：『人声听不清楚』）〔2026-10-27〕
- BGM 闪避：B、C、JP 尾板都在台词/口播处按整句平滑压低——提前压，说完多停一会儿再慢慢回升，两句之间的短停顿不回升；不用快速侧链（sidechaincompress），不写死音量，以人声清楚、BGM 还听得到为准；实现是一条连续 audio 加 `gain` 增益曲线（`scripts/mmkit/audio.py` 的 `duck_points()` 生成，格式见 render.py 文件头），不再拆成多段 audio 用 fade 衔接（用户：侧链『一惊一乍』；拆段首尾各自淡变会出音量凹坑）〔2026-11-05/11-12〕
- 口播期间压低 BGM 和音效，尾板音效不能盖住口播；最后一句口播完整说完后 BGM 才淡出，结尾留 ≥ 1 s；用 ASR 核对末字没被盖住（签售会改了三次『没说完』）〔2026-11-04〕
- 视频模型生成的错误人声要静音：ASR 认不出词但有能量、音色和角色对不上 → 对画面确认 → 只静那段原声，画面照常；原声里和前面重复的段落也静音或剪掉（每条新视频都会混进异常人声）〔2026-10-21〕。timeline 里怎么静见 rules/工程交付.md
