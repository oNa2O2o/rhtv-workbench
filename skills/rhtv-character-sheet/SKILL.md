# rhtv-character-sheet · 人设图总则

> **本文件必须从第一行完整读到最后一行，不得用 offset/limit 截断或只读片段。**
> **为什么**：这里每一节都是用户骂过才定下的规则，漏读任何一节都会重犯。
> **读完的证明**：在开始建节点或生成之前的那条回复里（被当作子代理调用时，在你输出的开头），列出：①第一节红线的原文边界词（“脖子根部到肚脐上方”“锁骨、胸口、V 领里的皮肤都算违规”“胸部不大于 B 罩杯”“肚脐下方到膝盖上方”“薄丝袜不算遮挡”）；②第二至七节各一句核心要求；③第九节末尾的确认口令。缺任何一项就是没读完，回去重读。

## 一、尺度红线（硬性，按字面执行，不许自己放宽或收紧）

用户原话：不可以——胸部大于 B、乳沟、正面脖子到肚脐上方露肤、肚脐下方到膝盖上方露肤、光脚；可以——肩部可露、背部可小范围露。

执行口径：
1. 正面躯干从**脖子根部到肚脐上方**不露皮肤：锁骨、胸口、V 领里的皮肤都算违规。
2. 胸部**不大于 B 罩杯**（重点看侧面）。
3. 没有乳沟，也没有胸部沟线。
4. 没有激凸（衣服上的凸点）。
5. **肚脐下方到膝盖上方**不露皮肤；**薄丝袜不算遮挡**，裙摆必须盖住膝盖上沿，开衩不能露出膝盖以上。
6. 不能光脚，必须穿鞋。

允许露：用户原话允许的是**肩部、小范围后背**；手臂和膝盖以下的小腿不在禁区内，因此也可以露。

- **为什么**：这是投放审核线。曾把“正面脖子到肚脐不露”自行理解成“锁骨领口可以露”，被直接打回。转述会走样，所以边界词必须照原文用。
- 用户在对话里给出新的原话时以最新原话为准；其他文档（包括工作台）里的尺度写法与本节不一致时，以本节为准。用户没说过的情况（半透面料、打底裤等）记为“临界”并问用户，不要自己定。

## 二、交付物与目标

- **交付物**：每张参考图一张角色四视图——头肩正脸特写、正面全身、侧面全身、背面全身；全身完整入画；图上不得有文字、信息卡、水印。**为什么**：它是后面母版视频的角色参考，缺视角或带字都没法用。
- **目标：合规前提下尽可能擦边**。红线是上限，不是让角色变保守的理由：把身材曲线和允许露的部位做满，胸控制在 B 以内但保留自然弧度，不压成平板、不穿宽松。**为什么**：用户原话“我要的是在合规的前提下尽可能擦边的角色”；宽松、平板的版本即使合规也被打回（“衣服太丑”“没有身材曲线”）。
- **优先级**：红线 > 参考图服装的辨识度 > 擦边加强。擦边优先靠剪裁贴合、姿态和身材曲线做；在允许露的部位做小幅露出或加小件可以，但不能改掉服装的款式辨识度。

## 三、人物与服装原则

- **人物锁定**：脸型、五官、妆容、发型、眼镜、耳饰、痣等逐项照参考图，四个视图是同一个人。**为什么**：人设图要传给后面的母版视频，身份不一致会一路传下去。
- **服装保留参考图的特点和材质**：款式、面料、图案、关键配件保留。为满足红线做的遮挡、加长、补鞋、去危险道具，只做最小修改。参考图缺的部分（如只有上半身时的下装和鞋）由你补全，同样守红线和改色规则。**为什么**：参考图是设计师选定的造型，原服装的辨识度就是卖点；随意换装被否定过。
- **改色只改黑色**：参考图主体服装里的黑色改成亮色，其他颜色照参考图不改。袜子、鞋、配件这类小件是否跟着改，按用户确认过的先例（见分文档），没有先例就问。**为什么**：用户规定（“之后除了黑色要改色，其他的都不改”），把灰色改成粉色被要求改回。
- **人设靠穿法和道具体现**：可以调整穿法、加人设道具，不换掉整套衣服、不加整件外套，除非用户明确要求。与人设冲突的普通道具去掉并在汇报里说明。**为什么**：用户在“加外套”和“只靠穿法道具”两版之间选了后者。
- **新增要透明**：为擦边或人设新加的东西（小件、镂空、道具、丝袜等），以及模型自己画出来的参考图没有的东西，汇报时逐项列出，标明是有意加的还是模型自己加的。**为什么**：没单列的新增，用户分不清哪些是参考图原有的，等于替用户做了决定。
- **需要用户定的事不阻塞出图**：没有先例的小件颜色、用户没说过的情况等，先按最贴近参考图的默认方案出，在汇报里列进“需要你决定”。**为什么**：用户要快；问完再跑多一轮来回，答案又常常就是默认方案。
- **模型固定，不提议换模型**：尺度压不住时靠服装结构、提示词和局部修改解决。**为什么**：用户原话“不换模型，自己通过调整内衣解决”。
- 用户中途改需求时立刻按新要求改，并把它当作之后所有版本的规则，记进失败日志。**为什么**：同一工程的多个版本是同台词换角色，规则必须一致。

## 四、质检原则（交给用户之前）

- **先自查**：每张图放大逐条对照第一节和第三节，大特写、正面胸口、侧面胸部、裙摆膝盖、鞋、背面都要看。只看整图缩略不算检查。**为什么**：漏看激凸、漏看裙子、漏看乳沟都发生过。
- **再独立审核**：至少两个独立审核员——一个只按红线挑错，一个看造型、擦边程度和还原度；两个都必须拿到第一节原文。尺度项拿不准一律判不过。**为什么**：自己看自己的图会放过问题；不给造型审核员红线，它会提出越线建议。
- **审核意见要取舍**：审核员会互相矛盾，也会提越线建议；逐条判断，向用户说明采纳了什么、没采纳什么、为什么。**为什么**：审核员曾建议“解开领口、露大腿”，照单全收就会越线。
- **每次重出都全项复查**：改好一处常让另一处回退。
- **按问题大小选修法**：其他项都对、只剩局部问题（胸、开衩、道具）时，直接“以上一张图为输入、只改局部”；问题不只是局部的，先整图重出；整图反复重出仍不收敛，转局部修改；局部修改也解决不了，停下把现状和可选方案报给用户定。不要无限加狠整图提示词。**为什么**：模型改一处回退另一处，盲目重出只烧积分。
- **交付时说实话**：哪条过、哪条临界、哪条没过，原样告诉用户；临界项对内按不过处理，修不动了再交用户定，最终是否合格由用户决定。**为什么**：把临界说成合格，用户发现后要重来一轮，比当场说清更费时间和积分。
- **快不能牺牲合格**：用户催快时，压缩沟通和等待，但不跳过放大自查和独立审核。**为什么**：漏检返工更慢、更费积分。

## 五、花费原则

- 花费只记 **RH 积分**，以 RH 账单为准。报价为 0（免费额度）不等于没花钱，**永远不对用户说“花费 0”**；账单确认扣 0 的，要说明是免费额度。
- 跑之前告诉用户预计次数和积分，说完就跑。要超出已报预估时：属于正常迭代（多一次重出或局部修改）的，先说明原因和新增积分再跑；因为修不动而继续加码的，停下让用户定。
- 中途停批量必须确认后台进程真的停了，没派发的不能再跑。
- **为什么**：用户按积分管成本；“花费 0 元”的说法和停不干净导致的白扣都被追责过。

## 六、画布原则

- 一张参考图对应一个版本列（同一角色有多张参考图时，按用户指定合成一个版本，拿不准就问），人设图放在该版本列里；状态（生成中 / 待审核 / 通过）在节点名里看得出来，自查和独立审核都做完才标待审核。工作台工程里命名和列位由工作台脚本管理，以分文档为准。
- 用户确认后，画布上只留过审的图。删除要有用户的明确指示（如“只留合格的”）或明确同意；删除前在回复里列出要删的节点。用户放的参考图、文字卡不删。工作台工程里同样适用本条，工作台脚本会自动删节点的操作也要先确认。
- **为什么**：画布是给设计师审的，废稿会误导审核；删除无法撤销，参考图是设计师的输入。
- 在工作台工程里，生成、采用、记账都走工作台脚本，保证本地物料和账本一致。

## 七、分文档（到这一步之前，必须先完整读对应那一份，同样不得截断）

| 到哪一步 | 必读 |
|---|---|
| 写或改提示词（版式、人物锁定、服装改法、身材、尺度、局部修改） | `references/提示词模板.md` |
| 出图后自查（裁切、怎么量胸和膝盖、模型常见毛病） | `references/尺度自查.md`，裁切用 `scripts/crops.py` |
| 派独立审核员、汇报审核结果 | `references/审核员.md`，脚本 `scripts/review_workflow.js` |
| 建节点、跑图、改名、挪位、删除、查积分 | `references/画布与积分.md`；不在工作台记录里的画布用 `scripts/canvas.py` |
| 遇到没见过的问题、想看以前怎么解决 | `references/案例-病娇女教师.md`、`references/失败日志.md` |

**为什么**：具体的坑（例如提示词写多少会被画成多少）全在分文档里，总则不重复；不读就动手会重犯。

## 八、出错与更新

- 出了新错误、用户纠正了新规则：先记进 `references/失败日志.md`；属于原则级的，提议用户更新本文件，用户同意后再改。改第一节时，必须同步 `references/审核员.md` 和 `scripts/review_workflow.js` 里的红线副本，保持逐字一致。**为什么**：总则只能由用户确认的原则组成，具体经验留在分文档，避免总则越写越长、越写越具体。

## 九、适用边界与确认口令

✅ 该用：“参考图放画布上了，出人设图”；“这张胸太大/裙子太短，改”；“剩下几个角色的图出了”；“衣服太丑，没曲线，要擦边”；“这些人设图合格吗”。

❌ 不该用：平面广告图、KV、静态投放素材（MM-P / doki-p）；不在 RHTV 画布上、用 api2img 批量出人设图（character-sheet-batch）；分镜图、母版视频、视频提示词（工作台对应步骤或 2.5prompt）；只是把已有人设图放到画布（rhtv-workbench 的 put）；写剧本台词（shortdrama-copy）。

确认口令：**红线原文、擦边做满、只改黑色、两审一取舍、只记积分、删前确认**。
