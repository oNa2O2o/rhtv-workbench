# 审核员：派两个独立审核员审人设图

为什么要审、审到什么程度，见总则第四节。本文件只写：什么时候派、怎么准备输入、怎么调用、两个审核员各管什么、意见怎么取舍、结果怎么报给用户。

脚本：`scripts/review_workflow.js`（Claude Code Workflow 工具用）。没有 Workflow 工具时，按第 4 节用 Agent 工具手动起两个子代理，提示词和脚本里的一致。

---

## 1. 什么时候派

1. 出图 → 下载 → `scripts/crops.py` 裁切 → 先看 `0全图` 核对裁切切在四格的缝上（见第 2 节）→ 按 `references/尺度自查.md` 自查。
2. 自查发现尺度不过或临界（看不清）的，对内都按不过处理，先按 `references/尺度自查.md` 1.4 选修法改（直接局部修改、先整图重出，或停下交用户定），对新图再走一遍。自查发现用户没定过的情况（半透面料、打底裤等），记“临界（规则未定）”、在汇报里列进“需要你决定”，不要自己判，也不在答复前为它自行加遮挡；它不挡审核，审核照常派（总则第一节末尾、第三节）。自查没发现要改的，派审核。
3. 两份审核结果都回来、按第 6 节取舍完，才标待审核（总则第六节）：工作台工程用 `wb adopt … --review`，其他画布改节点名，具体见 `references/画布与积分.md`。`wb adopt` 到已有节点的槽位会自动删掉旧节点，先按 `references/画布与积分.md` 〇.4 的删除口径办：用户有明确指示（如“替换掉”“只留合格的”）时，在回复里列出会被删的旧节点名和 ID 后执行；没有明确指示时，列出来先问，等用户明确同意。
4. 每次重出、每次局部修改得到的新图，都要重新裁切、重新派两个审核员、全项重审。不能只审改过的那一处（G2 改好一处常让另一处回退）。

## 2. 准备输入（每张图一组）

| 字段 | 必填 | 写什么 | 从哪来 |
|---|---|---|---|
| `tag` | 是 | 版本 + 轮次，如 `v4r5`、`v4fix` | 自己定，和裁切文件名前缀一致，方便对账 |
| `ref` | 是 | 参考图本地路径。同一角色的多张参考图合成一个版本时用数组：哪几张合成一个版本、各部分以哪张为准，按用户指定，拿不准先问用户（总则第六节），并把合成方式写进 `outfit` | 用户放进工程的参考图；画布上的参考图先下载（见 `references/画布与积分.md`） |
| `head` | 是 | 头部特征逐项清单 | 直接复制本轮提示词「人物：完全照参考图」段里那一串 |
| `outfit` | 是 | 参考图服装的特点 + 本次有意做的全部改动 | 本轮提示词「人设/服装」段的要点，逐项写：为守红线做的改动（加长裙、高领打底、扣到领口、补鞋）、改色（哪件黑色改成什么色）、没有先例的小件颜色（按最贴近参考图的默认方案出了什么色，写明是默认方案、等用户定）、补全的部分（参考图缺的下装、鞋）、**新增项**（参考图没有、这次加的小件、镂空、道具、丝袜等，写明为擦边还是为人设，有先例的写先例）、**去掉的东西**和原因（危险道具、与人设冲突的普通道具） |
| `crops` | 是 | 8 个裁切路径，**必须按序号 0–7 排列** | `scripts/crops.py` 打印的路径 |
| `persona` | 否 | 人设一句话，如「日本学校保健室里成熟妩媚的女老师」 | 工程的人设。不填就不审人设项（g）。也可以放在 args 顶层，作为所有图的默认值 |

8 张裁切的序号和用途（两个审核员的提示词按这个序号引用，顺序错了审核就会看错地方）：

| 序号 | 内容 | 主要用来看 |
|---|---|---|
| 0 | 全图缩到 1/3 | 整体、布局、开衩全貌；核对裁切切得对不对 |
| 1 | 第 1 格（头肩大特写）全高，缩到 2/3 | 正脸、头部一致、领口 |
| 2 | 第 1 格，高 45%–100%，原分辨率 | 领口露肤、乳沟、激凸 |
| 3 | 第 2 格（正面全身），高 8%–48%，原分辨率 | 领口露肤、乳沟、激凸、肚脐以上 |
| 4 | 第 3 格（侧面全身），高 8%–48%，原分辨率 | 胸是否超 B、激凸 |
| 5 | 第 2 格左边界到图右边缘，高 50%–85%，原分辨率 | 裙长、开衩、丝袜下的大腿 |
| 6 | 第 2 格左边界到图右边缘，高 82%–100%，原分辨率 | 是否穿鞋 |
| 7 | 第 4 格（背面全身）全高，缩到 2/3 | 后开衩、后背露出范围 |

- 四格的竖向分界由 `crops.py` 按白底留白自动找，不是四等分：G2 画的头肩大特写格通常占宽度 1/3 以上。stderr 会打印分界模式和 x 分界。
- 自动分界失败时脚本会退回四等分并在 stderr 提示。不管哪种模式，都先看 `0全图` 和 3、4 号裁切：切歪了（例如 3 号只剩半个人、4 号混进正面的手臂）就用 `--cuts X1,X2,X3` 手动给分界重切。裁切不对就不要派审核员。

`outfit` 写不全的后果：造型审核员会把你有意做的改动判成“没保留参考图服装”或“违反改色规则”，它列出的新增项也对不上。例如 v2、v4 通过版的膝下黑色薄丝袜是用户确认过的先例（v4 参考图本来没有丝袜，是新增），本轮也加了就要写进 `outfit`，否则它会被当成“模型自己加的”（`declared: false`）列出来，有意加和模型自己加就分不清了。

- 上面的 `outfit` 只示意写法：哪些是参考图原有、哪些是新增，以你手上的参考图和本轮提示词为准。
- 裁切文件名以 `crops.py` 实际打印的为准，上面只示意顺序。

返回值是数组，每张图一项：

```
{
  tag: "v4fix",
  scale: { items: [6 条 {item, pass, borderline, evidence}], cup_estimate, other_concerns, overall_pass, fix, script_notes },
  style: { items: [6 或 7 条 {item, pass, borderline, evidence}], cup_estimate, redline_concerns,
           additions: [{item, declared, note}], removals: [{item, declared, note}], overall_pass, fix, script_notes },
  summary: {
    scale_pass, style_pass, cup: {scale, style},
    scale_failed, scale_borderline,      // 尺度不过的条目；其中临界的（已按不过处理）
    user_undecided,                      // 尺度里用户没定过的情况（evidence 以「用户未定：」开头），要问用户
    scale_other_concerns,                // 6 条以外的尺度疑点，如后背露出范围
    style_failed, style_borderline,      // 造型不过的条目；造型临界项（如实报告，不强制判不过）
    style_redline_concerns,              // 造型审核员顺带看到的疑似越线
    disputes,                            // 两人对尺度意见相左的提醒（胸按罩杯字母粗判，以你对比 cup 为准）
    additions, undeclared_additions,     // 新增项；其中服装说明里没写的（模型自己加的）
    removals, undeclared_removals,       // 去掉或改掉的；其中服装说明里没写的（模型弄丢的）
    missing                              // 没返回结果的审核员
  }
}
```

脚本做的硬性兜底（`script_notes` 里会写明）：
- **只对尺度项**：标了 `borderline: true` 却判 `pass: true` 的条目，一律改成 fail（尺度项拿不准判不过）；evidence 写了「用户未定」的条目，一律记为临界、不过。
- **造型项不兜底**：造型审核员的 `borderline` 原样保留，`pass` 以它的判断为准，临界项在 `summary.style_borderline` 里如实列出。
- 两边的 `overall_pass` 和逐条结果不一致时，都按逐条结果重算。

## 4. 调用方式 B：Agent 工具（没有 Workflow 工具时）

- 每张图起两个子代理：一个尺度审核员、一个造型审核员。**在同一条消息里同时发出**所有 Agent 调用（多张图就一次发 2×N 个），让它们并行、互不知道对方的结论。
- 两个审核员都必须拿到下面提示词里的红线原文。不要删减，也不要只给造型审核员参考图不给红线（第 6 节教训）。
- 把 `{...}` 占位符换成第 2 节准备好的内容。
- 收到结果后，自己做第 3 节的兜底：尺度项 `borderline: true` 或 evidence 写了「用户未定」的条目一律按不过；造型项的 `borderline` 不改，如实报告；两边 `overall_pass` 按逐条结果重算。再自己整理出第 3 节 `summary` 里那几类清单（尤其是新增项和两人相左的项）。

### 4.1 尺度审核员提示词

```
你是买量素材的尺度审核员，非常严格：你的职责是挑出违规，不是放行。

用 Read 工具逐张打开下面 8 张图。它们是同一张「角色设定四视图」的整图和局部裁切；四视图从左到右：第 1 格头肩大特写、第 2 格正面全身、第 3 格侧面全身、第 4 格背面全身（四格按留白自动分界，大特写格通常比其他格宽）。8 张都要打开看，只看整图缩略不算审核：
- [0 全图（整张缩到 1/3）] {CROP0}
- [1 大特写（第 1 格全高，缩到 2/3）] {CROP1}
- [2 大特写胸口（第 1 格，高 45%-100%，原分辨率）] {CROP2}
- [3 正面躯干（第 2 格，高 8%-48%，原分辨率）] {CROP3}
- [4 侧面躯干（第 3 格，高 8%-48%，原分辨率）] {CROP4}
- [5 裙摆膝盖（第 2-4 格，高 50%-85%，原分辨率）] {CROP5}
- [6 鞋（第 2-4 格，高 82%-100%，原分辨率）] {CROP6}
- [7 背面（第 4 格全高，缩到 2/3）] {CROP7}

【尺度红线（用户给的审核线，硬性，按字面执行，不许自己放宽或收紧）】
用户原话：不可以——胸部大于 B、乳沟、正面脖子到肚脐上方露肤、肚脐下方到膝盖上方露肤、光脚；可以——肩部可露、背部可小范围露。

执行口径：
1. 正面躯干从**脖子根部到肚脐上方**不露皮肤：锁骨、胸口、V 领里的皮肤都算违规。
2. 胸部**不大于 B 罩杯**（重点看侧面）。
3. 没有乳沟，也没有胸部沟线。
4. 没有激凸（衣服上的凸点）。
5. **肚脐下方到膝盖上方**不露皮肤；**薄丝袜不算遮挡**，裙摆必须盖住膝盖上沿，开衩不能露出膝盖以上。
6. 不能光脚，必须穿鞋。

允许露：用户原话允许的是**肩部、小范围后背**；手臂和膝盖以下的小腿不在禁区内，因此也可以露。

【用户没定过的情况】例如半透明面料下透出皮肤、用不透明打底裤代替裙子遮挡、后背露出是否还算“小范围”：不要自己判过或不过，记为临界，写明是什么情况、在哪张裁切，由主代理去问用户。

【每条去哪看、怎么判】
- 第 1 条：看裁切 1、2、3，肚脐以上的腰腹再对照 0。从脖子根部到肚脐上方，锁骨、胸口、V 领开口里只要露出一点皮肤就是 fail；领口要贴到脖子根部。
- 第 2 条：重点看裁切 4（第 3 格侧面），再对照 2、3。看胸部最前点相对下胸围/腰线向前凸出多少。经验参考（以前的审核员用过，不是用户给的标准）：前凸不超过约 0.15 个头长，在 3840 宽的原图上约 40px（裁切 2-6 是原分辨率）。
- 第 3 条：看裁切 2、3，特别是领口和 V 领底部、胸前衣服的褶皱，有没有乳沟或胸部沟线。
- 第 4 条：看裁切 2、3、4，胸点位置的衣服上有没有凸点。挂在胸前的道具（如听诊器的黑色耳塞）正好落在胸点上、看着像凸点、分不清时，判 fail 并写明。
- 第 5 条：看裁切 5、7 和 0，三个全身视图都要看。按红线字面判：裙摆盖住膝盖上沿就过；看得到膝盖骨上缘或更上面的大腿（被丝袜盖着的也算）就 fail；裙摆压在膝盖上沿附近看不清，按拿不准判 fail。找膝盖的经验估计：身高从头顶量到鞋底，膝盖中心约在离地 28% 身高处，膝盖上沿在中心上方一点——这只帮你定位，不是判定线，不要求裙摆低于膝盖中心。开衩顶端在膝盖以下不违反红线；开到膝盖上沿或以上、或看不清顶端在哪，判 fail。
- 第 6 条：看裁切 6，三个全身视图都必须穿鞋。
- 允许露的部位（肩部、小范围后背、手臂、膝盖以下的小腿）露出来不算违规，不要因此判 fail。后背看裁切 7：露出范围大到拿不准还算不算“小范围”，写进 other_concerns，按用户没定过的情况处理。

【输出要求】只输出一个 JSON 对象，不要任何其他文字：
{"items":[{"item":"1 脖子根到肚脐上方不露","pass":true,"borderline":false,"evidence":"..."}, ...共 6 条...],"cup_estimate":"...","other_concerns":"...","overall_pass":false,"fix":"..."}
- items 正好 6 条，按 1-6 顺序；item 写编号和简称（如「2 胸≤B」）。
- 每条给 pass。拿不准就判 fail：pass 设为 false、borderline 设为 true，并在 evidence 里写为什么拿不准。
- 属于用户没定过的情况：pass 设为 false、borderline 设为 true，evidence 以「用户未定：」开头写清是什么情况。
- evidence 写：在哪张裁切（编号）、什么位置、看到了什么。
- cup_estimate 写你从侧面格估计的罩杯（如 A、A-B、B、B/C 临界、C）。
- other_concerns：6 条以外、和用户原话有关的疑点（例如后背露出是否还算小范围、6 条都套不上的用户没定过的情况），写裁切编号和位置；没有写「无」。
- overall_pass 只有 6 条全部 pass 才为 true。
- fix：没过的条目具体怎么改（哪个视图、哪个部位、改成什么）；用户没定过的条目可以写改法，但注明要等用户定；6 条全过写「无」。
只做审核，不要修改或创建任何文件。
```

### 4.2 造型审核员提示词

没有人设时删掉 g 那一行，并把“共 7 条”改成“共 6 条”。

```
你是买量素材的造型审核员。先用 Read 工具打开参考图（有多张时每张都打开：它们是同一个角色的参考图，按用户指定合成一个版本，哪部分以哪张为准见服装说明）：
- {REF}
再逐张打开生成的「角色设定四视图」整图和局部裁切（四视图从左到右：第 1 格头肩大特写、第 2 格正面全身、第 3 格侧面全身、第 4 格背面全身；四格按留白自动分界，大特写格通常比其他格宽）：
- [0 全图（整张缩到 1/3）] {CROP0}
- [1 大特写（第 1 格全高，缩到 2/3）] {CROP1}
- [2 大特写胸口（第 1 格，高 45%-100%，原分辨率）] {CROP2}
- [3 正面躯干（第 2 格，高 8%-48%，原分辨率）] {CROP3}
- [4 侧面躯干（第 3 格，高 8%-48%，原分辨率）] {CROP4}
- [5 裙摆膝盖（第 2-4 格，高 50%-85%，原分辨率）] {CROP5}
- [6 鞋（第 2-4 格，高 82%-100%，原分辨率）] {CROP6}

用户要的是：在尺度合规的前提下尽可能擦边的角色。下面的尺度红线是硬性上限。你不负责逐条判红线（另有尺度审核员），但你的任何修改建议都不能违反它：
```

## 5. 两个审核员的职责和判定口径

| | 尺度审核员 | 造型审核员 |
|---|---|---|
| 看什么图 | 只看生成图的 8 张裁切，不看参考图（红线只和生成图有关） | 参考图 + 8 张裁切 |
| 审什么 | 红线 1–6 逐条；6 条以外的疑点（如后背露出范围）写进 `other_concerns` | a 布局、b 头部一致、c 服装保留、d 改色、e 擦边曲线、f 好看/AI 畸形、g 人设（有 persona 时）；另列新增项、去掉项 |
| 拿不准时 | 判不过（`pass: false` + `borderline: true`），脚本强制执行 | 标 `borderline: true`，`pass` 由它自己判；脚本不改，如实报告，不强制判不过 |
| 用户没定过的情况 | 判不过 + `borderline: true`，evidence 以「用户未定：」开头 | 写进 `redline_concerns` |
| 裙摆 | 按红线字面：盖住膝盖上沿即过；膝盖中心线只是帮助定位的经验估计；膝下开衩不违规 | 不判 |
| 允许露的部位 | 露了不算违规，不许因此判不过（不收紧） | 参考图本来露的应保留；参考图没露的不要求露，可以作为擦边建议（小幅露出，不改服装辨识度，写明是新增） |
| 修改建议 | 只写怎么改到合规 | 必须在红线内、不改服装辨识度、不建议换模型；做不到的写「红线内无法改进」 |
| 额外输出 | `cup_estimate`、`other_concerns` | `cup_estimate`（给你交叉核对胸）、`redline_concerns`、`additions`、`removals` |
| 不负责 | 好不好看、像不像参考图 | 逐条判红线 |

- “拿不准判不过”只用于尺度项（总则第四节）；造型项拿不准的如实写“临界”交给你取舍，不强制判不过。
- 提示词里写“膝下约 10 厘米、裙子不开衩”是为了抵消 G2 把裙子画短的毛病，是写法经验，不是判定标准。图上裙子比提示词短、或出现膝下开衩，只要满足红线字面就不算尺度不过；没按提示词画的地方要不要下一轮改由你取舍，汇报里不要把它写成红线不过。
- 具体量法（膝盖位置、侧面胸前凸、丝袜、开衩、激凸和道具的区分）见 `references/尺度自查.md`；审核员提示词里给的是同一套口径的简版。

## 6. 怎么取舍审核意见

审核员说的不一定对，也不一定互相一致。逐条按下表处理，并在汇报里写清采纳了什么、没采纳什么、为什么（总则第四节）。

| 情况 | 怎么处理 |
|---|---|
| 尺度审核员判某条不过（含临界） | 打开它 evidence 里点名的裁切亲自复核。能明确看出它看错了（比如把允许露的膝下小腿当成大腿，或把膝下开衩当成过膝），写明理由后可以不采纳，汇报里仍要列出它的原判；不能明确推翻，就对内按不过处理，能修先修（见表后“怎么修”） |
| 尺度里有用户没定过的情况（`summary.user_undecided` 或 `other_concerns` 里提到，例如半透面料透出皮肤、打底裤、后背露出是否还算小范围） | 不自己判过或不过。汇报里记“临界（规则未定）”，放进“需要你决定”问用户，同时给出可选改法和积分预估。它不阻塞其他工作：其他项照常推进，不为等答复停跑；答复前也不为这一项自行加遮挡、改结构（总则第一节末尾、第三节）。用户答复后照办，并把答复记进 `references/失败日志.md`（总则第八节） |
| 两人对尺度意见相左（`summary.disputes`；或两人的 `cup_estimate` 一个在 B 以内、一个超 B；或尺度判过、造型 `redline_concerns` 指出疑似越线，你复核也排除不了） | 不自己挑一个当结论。对内按不过处理，按表后“怎么修”修，改完全项重审。到了 `references/尺度自查.md` 1.4 的停下条件（例如局部修改后这一项没变化）；整图重出后两人仍相左的，按 1.4 继续修时，停下，把两人的原判（`cup_estimate`、evidence）和对应裁切原样报给用户定。先例：v2 擦边版局部修改改胸后胸几乎没变（修不动），v2fix 尺度审核员判 B/C 临界不过、造型审核员判 A–B 过，如实报给用户后用户确认通过 |
| 造型审核员某条标了临界（`summary.style_borderline`） | 不强制判不过。在汇报里如实写“临界”和依据；值不值得下一轮改，由你按优先级（红线 > 服装辨识度 > 擦边加强）取舍，并说明理由 |
| 新增项里有服装说明没写的（`summary.undeclared_additions`，即模型自己加的） | 亲自看，每一项都列进新增项清单、标“模型自己加”，不管最后留不留（总则第三节“新增要透明”）。然后分两种：① 主体服装上的黑色单品（例如多出一件黑色打底、黑色裙子）→ 违反只改黑色，必须去掉，修法按表后“怎么修”；② 其他的（袜子、鞋、配件、道具、镂空等；包括膝下黑色薄丝袜——它有 v2、v4 的先例，但这一轮不是有意加的）→ 二选一并在汇报里写明选了哪个：列进“需要你决定”问用户留不留，或下一轮提示词点名去掉。危险道具、与人设冲突的普通道具选“点名去掉”（总则第三节）。不要只因为它是模型自己加的就判服装项不过，也不要默认保留 |
| 去掉项里有服装说明没写的（`summary.undeclared_removals`，即模型弄丢了参考图的东西） | 属于 c 条（服装保留）问题，要补回，修法按表后“怎么修”（其他项都对、只差这一两处小件时属于局部问题） |
| 造型审核员建议越线（解开领口、露锁骨、开 V 领、裙子改短、露大腿、放大胸） | 直接不采纳，汇报里写“越线，未采纳”。先例：造型审核员第一次没拿到尺度标准，建议“解开领口、露大腿”——所以现在两个审核员的提示词都内嵌红线原文 |
| 造型审核员建议换颜色、换款式、加整件外套，或为了擦边改掉服装辨识度 | 按总则第三节和优先级判断：只有主体服装的黑色改亮色；不换整套、不加整件外套，除非用户要求；擦边加强不能盖过服装辨识度。不符合就不采纳并写明原因 |
| 造型审核员建议换模型 | 不采纳（总则第三节：模型固定） |
| 造型审核员说“没曲线 / 太保守 / 衣服丑” | 是真问题：用户以“衣服太丑”“没有身材曲线”打回过合规版本（总则第二节）。在红线内、不改服装辨识度的前提下，靠剪裁贴合、姿态、身材曲线加强，措辞见 `references/提示词模板.md`；在允许露的部位做小幅露出或加小件也可以，但算新增，要列出 |
| 造型审核员判“胸压成平板”（e 条），尺度审核员判胸过 | 两者不矛盾：目标是 B 以内但有自然弧度。下一轮在胸的写法上放一点弧度，同时全项复审 |
| 第 3 格人朝左 | 只记录，不算问题（用户暂未要求修正） |
| 某个审核员没返回结果 | 这张图只审了一半，不能标待审核（工作台工程里不能 `adopt --review`）；只对这一张重派 |

**怎么修**（原则见总则第四节）：
- 直接局部修改、先整图重出、什么时候算不收敛、什么时候停下交用户定，全部按 `references/尺度自查.md` 1.4 办，本文件不另立条款；局部修改和重出的措辞见 `references/提示词模板.md`。
- 停下交用户定时，除了 1.4 要求的现状和可选方案（含各自预计次数和积分），还要附上两个审核员的原判（`cup_estimate`、evidence）和对应裁切。
- 要超出已报给用户的积分预估时按总则第五节：属于正常迭代（多一次重出或局部修改）的，先说明原因和新增积分再跑；因为修不动而继续加码的，停下让用户定。
- 改完的新图回到第 1 节：重新裁切、自查、两个审核员全项重审。
