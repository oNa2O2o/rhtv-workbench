# rhtv-workbench · 视频素材自动化工作台

工作台只负责**约束**：画布怎么命名、工程怎么排、素材放哪、什么时候停下等审核、花费怎么记。具体制作交给现有 Skill（shortdrama-copy、2.5prompt、mm-packager、xmp-upload 等）。

**怎么调用脚本**：脚本在本 SKILL.md 所在目录的 `scripts/wb.py`。路径可能带空格，**永远加双引号**：

```
python "<本 SKILL.md 所在目录>/scripts/wb.py" <命令> ...
```

下文简写为 `wb <命令>`。脚本只输出 JSON：`ok:true` 成功；`ok:false` 读 `error` 原样告诉用户，**不要自己重试同一个写操作**；`warnings` 里的提示要转告用户。
所有画布写入都走 wb，不要裸用 rhtvcli（它不在 PATH 里，长参数还会被 .cmd 截断）；需要 rhtvcli 的只读查询用 `wb rh <rhtvcli 参数>`。

## 〇、优先级

在工作台流程里，**本 Skill 的规定优先于被调用 Skill 里“先问用户 / 让用户确认”的步骤**：
- 在画布上跑生成**直接跑，不问用户**（rhtvcli 帮助里写的“付费须用户同意”在这里视为用户已同意）。
- 2.5prompt 里“要不要做 3D”“先确认 3D 镜头方案”“问画风”：不问。有转头、转身、换场景的镜头就做 3D；画风沿用项目已有设定。所有产出一起放上画布、标待审核，让设计师一次审。
- 模型、版本数不问，用 `wb list` 返回的 `defaults`（第六节）。
- 只有两种情况停下来问：审核关卡（产出放上画布后）、用户需求本身不明确（例如没给素材也没给需求）。

## 〇·五、日志（必须做）

从安装开始，所有问题都要留记录，维护者靠这些日志改进 Skill：
- wb 的每次运行都会自动记进 `~/.rhtv-workbench/logs/运行日志.jsonl`；安装器的每一步记进同目录的 `安装日志.jsonl`。
- **你自己遇到的问题也要记**：任何报错、卡住、需要绕路、Skill 写得不清楚、用户纠正你的地方，马上
  `wb log --problem "<发生了什么、在哪一步、怎么绕过的>" --stage <阶段> --project <工程>`；问题解决后再记一条 `wb log --fixed "<怎么解决的>"`。
- 用户说「导出工作台日志」「把日志发给我」：`wb report`，把生成在桌面的 zip 路径告诉用户。
- 用户问「最近有什么问题」：`wb log`（默认只列失败、警告和记录的问题）。

## 一、第一次使用：配置工作台

**新电脑**：把 https://github.com/oNa2O2o/rhtv-workbench 发给 Agent，按仓库 README 的「给 Agent：安装步骤」执行一条命令即可（公司内网优先用共享盘里的 `bootstrap.ps1`）。它会自动装好 Python 及依赖、ffmpeg、ElevenLabs CLI、rhTV 客户端，把全部 Skill 链接到本机所有 Agent 平台，默认装到容量最大的盘 `X:\RHTV工作台`，并打开浏览器让用户登录 rhTV / ElevenLabs。可重复运行：输出 `RESULT_JSON` 的 code 为 3 表示在等用户批准登录，提醒后原样再跑一次。
已经装过、只是在 Agent 里第一次用：

1. `wb check`：看 `login`。没装或没登录时，按 `references/安装与登录.md` 装好并让用户在浏览器里点一次批准（唯一需要用户动手的地方）。`pillow`/`ffprobe` 缺了只影响预览和尺寸精度，提示用户装即可。
2. 问用户两件事（只问一次）：设计师名字、本地工作目录。然后：
   ```
   wb setup --designer 钟海明 --root "F:/钟海明/RHTV工作台"
   ```
   它会在 RHTV 里找或建以设计师名字命名的文件夹，配置存在 `~/.rhtv-workbench/config.json`。
3. 检查制作用的 Skill 能否加载：shortdrama-copy、2.5prompt、mm-packager、xmp-upload。加载不到时直接读 `<skills 根目录>/<名字>/SKILL.md` 照做；都找不到就告诉用户缺哪个（不影响画布功能）。

## 二、画布规则（硬规则，改之前先和用户确认）

- **画布**：一个周期一张，放在设计师文件夹里，命名 `起始日-结束日-花费：N`，例如 `261110-261208-花费：2640`。周期从第一次新建画布那天起 28 天（结束日当天属于下一周期）；过期后的下一个新工程自动开新画布，上一周期没做完的工程继续在原画布里做完。N 是这张画布上所有工程在 RHTV 跑生成扣的**积分**（按每次运行前的官方报价换算，1 元 = 100 积分；G2 低价版 10 积分/次），每个工程交付时更新；报价为 0（免费额度）或不完整时名字末尾带 `+`，需要到 https://www.runninghub.cn/bill-task 核对实际积分后 `wb cost --name <工程> --add <差额积分> --settled`。**永远不要对用户说“花费 0”**，只说跑了几次、扣了多少积分（未核对就说未核对）。
- **每行一个工程**，包括它的全部迭代，从左往右横排；不同工程从上往下排。每行是一个分组，组名就是工程名 `日期-地区-名称`（如 `261104-JP-签售会POV`）。
- **行内顺序**：标题卡（工程名、进度、待审核/打回清单、版本数、花费、最近意见）→ 文案列（大纲、全量文案、补充文案）→ 提示词列（分幕提示词、音色参考、3D 参考视频）→ 之后**每个人设图一列**（= 一个版本 v1、v2…），列内从上到下：人设图 → 母版视频 → 包装视频。
- **只留最终版**：同一槽位再放入会替换旧节点；不要的版本用 `wb remove <工程> v3` 整列删掉。
- **审核标记**：节点名带【待审核】；打回后带【打回】；通过后去掉。
- **成品不上画布**，只放本地 `06_成品/`。
- 画布最左侧「工作台总览」卡列出本画布全部工程的进度和花费，脚本自动维护。
- 用户在画布上手动挪乱、删了节点或解散了分组：`wb layout` 会以画布为准修复记录并恢复标准排版。

## 三、本地文件夹（收集全部物料）

```
<工作目录>/<设计师>/<周期 261110-261208>/
  画布.json                 画布 ID、花费账本、工程顺序（脚本维护）
  排版预览.png              wb preview 生成
  <工程名>/
    工作台.json             这一行的槽位、节点、进度（脚本维护，不要手改）
    01_文案/ 02_提示词/ 03_人设图/ 04_母版/ 05_包装/ 06_成品/   被替换的旧文件在各自的 _旧版/
    修改记录.md             每次通过/打回/移除的原话（复盘用）
```

`put` 会把文件复制进对应子文件夹；`adopt` 会把画布产物下载进去。

## 四、用户怎么说 → 你做什么

| 用户说 | 做什么 |
|---|---|
| 配置工作台 | 第一节 |
| 新建工程 `261110-JP-名称` | `wb new 261110-JP-名称`，从 01 开始做。失败了可原样重跑一次 |
| 新建工程，已有剧本 / 已有人设图 / 已有视频 | `wb new <工程> --from 02/03/05`；把已有物料用 `put` 放进对应槽位（不加 `--review`，视为已通过），然后从该阶段做 |
| 继续 / 继续做 `<工程>` | `wb list` 看进度和槽位，做当前阶段的下一个子步骤；产出放上画布加 `--review`，**停下**，把画布链接和要审的内容告诉用户 |
| 通过 / 可以 | `wb approve <工程>`（只通过待审核的，不会把打回的一起通过）。本阶段还有子步骤没做就接着做；本阶段最后一个审核点通过后才 `wb stage <工程> <下一阶段> 进行中` |
| 部分通过、部分打回（如“v2 可以，v1 字太小”） | 先 `wb reject <工程> v1·包装 --note-file <原话.txt>`，再 `wb approve <工程>` |
| 打回 + 意见 | 把用户原话写进一个 UTF-8 文本文件，`wb reject <工程> [槽位…] --note-file <文件>`；按意见重做，重新 `put/adopt … --review` |
| 不要某个版本 / 删掉 | `wb remove <工程> v3` 或 `wb remove <工程> 3D参考` |
| 工作台进度 | `wb list`，一两句话汇报，给画布链接 |
| 重排画布 | `wb layout`（必要时 `wb preview` 看图核对） |

槽位写法：固定槽位直接写名字（`全量文案`、`3D参考`）；版本槽位写 `v<N>·<槽位>`（`v1·包装`），整列写 `v<N>`，也可以 `包装 --version 1`。写错时脚本会列出可用槽位。
用户没说工程名：`wb list` 的 `unfinished` 只有一个就用它，有多个就问一句。

## 五、每个阶段

每个阶段开始先 `wb stage <工程> <阶段号> 进行中`。

**01 文案**（shortdrama-copy，只出核心剧情）
1. 出 5 个大纲 → `wb put <工程> 大纲 大纲.md --review` → 停，等用户选。
2. 用户选定（如“用第 3 个”）→ 把只含选中大纲的文件 `put` 回 `大纲`（不加 review），`wb approve <工程>`。
3. 写全量文案 → `wb put <工程> 全量文案 全量文案.md --review` → 停。通过后进 02。

**02 提示词·音色·3D**（2.5prompt）
- 分幕提示词 → `put … 分幕提示词 提示词.md --review`
- 音色：按人设和剧情从音色库挑参考 → `put … 音色参考 <音频> --review`
- 有转头、转身、换场景的镜头就按 2.5prompt 的 3D 参考流程出 3D 视频 → `put … 3D参考 <视频> --review`
- 三样都放上去再停；全部通过后进 03。

**03 人设图**：版本数 = 文案里写的人设/造型数；没写就用 `defaults.versions_if_unspecified`。每个版本一张：
- 用户给了参考图：在画布上生成（第六节，`--left` 用上传的参考图节点或已有人设图），`adopt <工程> 人设图 --node <节点> --version N --label <造型> --review`；本地已有图就 `put <工程> 人设图 x.png --version N --label <造型> --review`。
- 尺度清单（不合格不要放上去，直接改到合格）：胸部小于 B；无乳沟；正面脖子到肚脐上方不露肤；肚脐下方到膝盖上方不露肤；不光脚；肩部可露；背部可小范围露。

**04 母版视频**：每个人设图一条。`wb gen <工程> --type video --prompt-file 提示词.txt --left v<N>·人设图 [--left 3D参考]` → `wb run` → `wb adopt <工程> 母版 --node <节点> --version N --review`。

**05 包装**（mm-packager）：先补全文案（口播、标题、目标、卡片字段）→ `put … 补充文案 补充文案.md --review`；再按版本包装（口播 + 划卡 + 介绍页 + 卡片尾板），母版用 `04_母版/` 里下载好的文件 → 每版 `put <工程> 包装 包装_vN.mp4 --version N --review`。

**06 成品交付**：成品、方版、横版只放本地：`wb deliver <工程> --file 成品1.mp4 --file 方版.mp4 …`（更新画布名花费）。用户要求上传投放时再用 xmp-upload。

**07 复盘**：读本地 `修改记录.md`，按各 Skill 的复盘规则列更新点给用户确认。不上画布。

## 六、在画布上跑生成（直接跑，不问用户）

1. 选模型：默认用 `wb list` 里的 `defaults`（`image_model` / `video_model`）。要换模型时 `wb rh model search <关键词> --type image|video` 找，再 `wb rh model <MODEL> --type image|video` 读实时 schema；参数只用 schema 里的字段名和取值。
2. 建节点：提示词写进 UTF-8 文件，
   ```
   wb gen <工程> --type image|video --prompt-file <文件> --left v1·人设图 [--left <节点ID>] [--set aspectRatio=16:9] [--model <MODEL>]
   ```
   返回 `node`。节点先放在本行上方的临时区。
3. 运行：`wb run <工程> --node <节点>`。它会先报价、带唯一请求 ID 运行并等结果：
   - `ok:true`：已按报价记账 → 第 4 步。
   - `pending:true`（退出码 4）：还在跑，已按报价记账。用 `wb wait <工程> --node <节点>` 继续等，**不要换 ID 重跑**，也不要先 adopt。
   - `ok:false`：失败，没记账。把 `errorMessage` 和 `code` 原文告诉用户。
4. 收进槽位：`wb adopt <工程> <槽位> --node <节点> --version N [--label 造型] --review`（自动下载到本地对应文件夹）。
5. 没被采用的生成节点用 `wb rh node delete id:<节点> -p <画布ID>` 删掉（画布 ID 在 `wb list` 每个工程的 `canvas_id`）；`wb layout` 的 `orphans` 会列出画布上不属于工作台的节点。

## 七、自定义

列宽、间距、行距等：在 `~/.rhtv-workbench/config.json` 加 `"layout": {...}`（键同 wb.py 的 LAYOUT），然后 `wb layout`。默认模型、默认版本数改 `"defaults"`。测试时用过 `--prefix 测试-` 的，正式使用前 `wb setup --designer … --root … --prefix ""` 清掉（list/check 会提醒）。

## 八、注意

- 不在 RHTV 上的花费（ElevenLabs、本地渲染）不计入画布花费。
- 跨平台：Windows 已验证；macOS/Linux 需要先按 rhTV 官方 USAGE.md 安装客户端，wb.py 会自动找 `~/.runninghub-canvas`。
