# rhtv-workbench · 视频素材自动化工作台

工作台只负责**约束**：画布怎么命名、工程怎么排、素材放哪、什么时候停下等审核、积分怎么记。具体制作交给现有 Skill（shortdrama-copy、2.5prompt、mm-packager、xmp-upload 等）。

**怎么调用脚本**：脚本在本 SKILL.md 所在目录的 `scripts/wb.py`。路径可能带空格，**永远加双引号**：

```
python "<本 SKILL.md 所在目录>/scripts/wb.py" <命令> ...
```

下文简写为 `wb <命令>`。脚本只输出 JSON：`ok:true` 成功；`ok:false` 读 `error` 原样告诉用户，**不要自己重试同一个写操作**；`warnings` 里的提示要转告用户。
所有画布写入都走 wb，不要裸用 rhtvcli（它不在 PATH 里，长参数还会被 .cmd 截断）；需要 rhtvcli 的只读查询用 `wb rh <rhtvcli 参数>`。

## 〇、优先级

**制作内容按制作 Skill 写**：工作台只管流程（什么时候做、放哪、何时停下审核），不规定剧情、提示词怎么写。调用 shortdrama-copy、2.5prompt、mm-packager 等制作 Skill 时：
- 先按该 Skill 自己写的「加载流程」把它要求读的文件**全部读完**再动手，不能只读 SKILL.md 或挑几份读；
- 交付给用户前，逐条过该 Skill 的检查清单，不合格的直接重写，不把半成品交给用户；
- 产出被用户否掉时，先对照该 Skill 找出自己哪一步没照做，**不要去改制作 Skill 的规则**（除非用户明确要求改）。

在工作台流程里，**本 Skill 的规定优先于被调用 Skill 里“先问用户 / 让用户确认”的步骤**：
- 在画布上跑生成**直接跑，不问用户**（rhtvcli 帮助里写的“付费须用户同意”在这里视为用户已同意）。例外：每个工程**第一次跑母版前**，在回复里列一行设置（模型、480p、高画质、时长、参考：人设图/3D/音频、预计积分）等用户确认；同设置的后续版本直接跑（单条母版约 2800 积分）。
- 2.5prompt 里“要不要做 3D”“先确认 3D 镜头方案”“问画风”：不问。有转头、转身、换场景的镜头就做 3D；画风沿用项目已有设定。所有产出一起放上画布、标待审核，让设计师一次审。
- 模型、版本数不问，用 `wb list` 返回的 `defaults`（第六节）。
- 只有三种情况停下来问：审核关卡（产出放上画布后）、用户需求本身不明确（例如没给素材也没给需求）、每个工程第一次跑母版前确认设置（见上）。

## 〇·五、日志（必须做）

从安装开始，所有问题都要留记录，维护者靠这些日志改进 Skill：
- wb 的每次运行都会自动记进 `~/.rhtv-workbench/logs/运行日志.jsonl`；安装器的每一步记进同目录的 `安装日志.jsonl`。
- **你自己遇到的问题也要记**：任何报错、卡住、需要绕路、Skill 写得不清楚、用户纠正你的地方，马上
  `wb log --problem "<发生了什么、在哪一步、怎么绕过的>" --stage <阶段> --project <工程>`；问题解决后再记一条 `wb log --fixed "<怎么解决的>"`。
- 用户说「导出工作台日志」「把日志发给我」：`wb report`，把生成在桌面的 zip 路径告诉用户。
- 用户问「最近有什么问题」：`wb log`（默认只列失败、警告和记录的问题）。

## 一、第一次使用：配置工作台

**新电脑**：把 https://github.com/oNa2O2o/rhtv-workbench 发给 Agent，按仓库 README 的「给 Agent：安装步骤」执行一条命令即可（公司内网优先用共享盘里的 `bootstrap.ps1`）。它会自动装好 Python 及依赖、ffmpeg、ElevenLabs CLI、rhTV 客户端，把全部 Skill 链接到本机所有 Agent 平台，默认装到容量最大的盘 `X:\RHTV工作台`，并打开浏览器让用户登录 rhTV / ElevenLabs。可重复运行：输出 `RESULT_JSON` 的 code 为 3 表示在等用户批准登录，提醒后原样再跑一次。
已经装过、只是在 Agent 里第一次用：

1. `wb check`：看 `login`。没装或没登录时，按 `references/安装与登录.md` 装好并让用户在浏览器里点一次批准（唯一需要用户动手的地方）。`pillow`/`ffprobe` 缺了只影响预览和尺寸精度，提示用户装即可。
2. 问用户两件事（只问一次）：设计师名字、本地工作目录。然后：
   ```
   wb setup --designer 钟海明 --root "F:/钟海明/RHTV工作台"
   ```
   它会在 RHTV 里找或建以设计师名字命名的文件夹，配置存在 `~/.rhtv-workbench/config.json`。
3. 检查制作用的 Skill 能否加载：shortdrama-copy、2.5prompt、mm-packager、xmp-upload。加载不到时直接读 `<skills 根目录>/<名字>/SKILL.md` 照做；都找不到就告诉用户缺哪个（不影响画布功能）。

**开工先查更新**：新建 / 继续工程开工先 `wb version --check`。`behind:true`（打印「上游 X，本机 Y，按 README 重跑 bootstrap 更新」）就先更新再干活；网络不通会说查不到，照常干。本机改过 skill 的，更新前先备份本机 skill，装完用三方合并（基线 = 本机改动前的上游版，另两方 = 本机版、新上游版）保留本机改动，冲突逐处看（0.4.0 + 本机改动 → 0.5.0 合出 5 处冲突，都是画布名 / 积分写法）。合完的 skill 改动要不要推上游，先问用户。

## 二、画布规则（硬规则，改之前先和用户确认）

- **画布**：一个周期一张，放在设计师文件夹里，命名 `起始日-结束日-设计师-积分：N`，例如 `261110-261208-钟海明-积分：26400`。周期从第一次新建画布那天起 28 天（结束日当天属于下一周期）；过期后的下一个新工程自动开新画布，上一周期没做完的工程继续在原画布里做完。N 是这张画布上所有工程在 RHTV 跑生成扣的**积分**（按每次运行前的官方报价换算：rhtvcli 报价单位是元，1 元 = 100 积分；G2 低价版 10 积分/次），每个工程交付时更新；报价为 0（免费额度）、不完整或按实际用量计费（如 Seedance 母版，跑之前没有报价）时名字末尾带 `+`。**积分以账单为准**：账单 https://www.runninghub.cn/bill-task（接口 `POST /uc/point/consumeList`），账单记录的 bizNo = rhtvcli 返回的 jobId（wb 账本自动记 jobId）；网页登录态在用户日常登录 RunningHub 的浏览器里（本机是 123 浏览器），不在内置浏览器。按 `references/积分对账.md` 只读拿到账单 json，`wb cost --reconcile <账单.json>` 按 jobId 填实扣积分、更新画布名、清掉 `+`；它列出对不上的才 `wb cost --name <工程> --add <差额积分> --settled` 手补。**不让用户去查账单、报数字**，拿不到就说缺什么。**永远不要对用户说“花费 0”**，只说跑了几次、扣了多少积分（未核对就说未核对）。
- **每行一个工程**，包括它的全部迭代，从左往右横排；不同工程从上往下排。每行是一个分组，组名就是工程名 `日期-地区-名称`（如 `261104-JP-签售会POV`）。
- **行内顺序**：标题卡（工程名、进度、待审核/打回清单、版本数、积分、最近意见）→ 文案列（大纲、全量文案、补充文案）→ 提示词列（分幕提示词、音色参考、3D 参考视频）→ 之后**每个人设图一列**（= 一个版本 v1、v2…），列内从上到下：（用户拖上来的参考图）→ 人设图 → 母版视频 → 包装视频。
- **只留最终版**：文字槽位再放入会替换旧节点；图、视频、音频要替换时先 `wb remove` 再 `wb put`（见第四节）；不要的版本用 `wb remove <工程> v3` 整列删掉。
- **审核标记**：节点名带【待审核】；打回后带【打回】；通过后去掉。
- **成品不上画布**，只放本地 `06_成品/`。
- 画布最左侧「工作台总览」卡列出本画布全部工程的进度和积分，脚本自动维护。
- 用户在画布上手动挪乱、删了节点或解散了分组：`wb layout` 会以画布为准修复记录并恢复标准排版。

## 三、本地文件夹（收集全部物料）

```
<工作目录>/<设计师>/<周期 261110-261208>/
  画布.json                 画布 ID、积分账本、工程顺序（脚本维护）
  排版预览.png              wb preview 生成
  <工程名>/
    工作台.json             这一行的槽位、节点、进度（脚本维护，不要手改）
    01_文案/ 02_提示词/ 03_人设图/ 04_母版/ 05_包装/ 06_成品/   被替换的旧文件在各自的 _旧版/
    修改记录.md             每次通过/打回/移除的原话（复盘用）
```

`put` 会把文件复制进对应子文件夹；`adopt` 会把画布产物下载进去。

## 四、用户怎么说 → 你做什么

| 用户说 | 做什么 |
|---|---|
| 配置工作台 | 第一节 |
| 新建工程 `261110-JP-名称` | 先 `wb version --check`（第一节末），再 `wb new 261110-JP-名称`，从 01 开始做。失败了可原样重跑一次 |
| 新建工程，已有剧本 / 已有人设图 / 已有视频 | 先 `wb version --check`；`wb new <工程> --from 02/03/05`；把已有物料用 `put` 放进对应槽位（不加 `--review`，视为已通过），然后从该阶段做 |
| 继续 / 继续做 `<工程>` | 先 `wb version --check`；`wb list` 看进度和槽位，做当前阶段的下一个子步骤；产出放上画布加 `--review`，**停下**，把画布链接和要审的内容告诉用户 |
| 通过 / 可以 | `wb approve <工程>`（只通过待审核的，不会把打回的一起通过）。本阶段还有子步骤没做就接着做；本阶段最后一个审核点通过后才 `wb stage <工程> <下一阶段> 进行中` |
| 部分通过、部分打回（如“v2 可以，v1 字太小”） | 先 `wb reject <工程> v1·包装 --note-file <原话.txt>`，再 `wb approve <工程>` |
| 打回 + 意见 / 提修改意见（没说打回也算） | 先 `wb reject <工程> <槽位> --note "<用户原话>"`（原话长就写进 UTF-8 文本文件用 `--note-file`），再按意见重做、替换，重新 `put/adopt … --review`。原话进 `修改记录.md`，第 07 步只看文件就能复盘 |
| 替换画布上的图 / 视频 / 音频 | 先 `wb remove <工程> <槽位> --note "<用户原话>"` 再 `wb put`（直接 put 不替换媒体）。画布上传上限约 50MB（报 LIMIT_EXCEEDED），超了另压一份画布版（CRF 21）上传，本地保留原片 |
| 不要某个版本 / 删掉 | `wb remove <工程> v3 --note "<用户原话>"` 或 `wb remove <工程> 3D参考 --note …`（`--note` / `--note-file` 写进 `修改记录.md`） |
| 工作台进度 | `wb list`，一两句话汇报，给画布链接 |
| 重排画布 | `wb layout`（必要时 `wb preview` 看图核对） |

槽位写法：固定槽位直接写名字（`全量文案`、`3D参考`）；版本槽位写 `v<N>·<槽位>`（`v1·包装`），整列写 `v<N>`，也可以 `包装 --version 1`。写错时脚本会列出可用槽位。
用户没说工程名：`wb list` 的 `unfinished` 只有一个就用它，有多个就问一句。

## 五、每个阶段

每个阶段开始先 `wb stage <工程> <阶段号> 进行中`。

**01 文案**（shortdrama-copy）
0. 加载 shortdrama-copy，按它的「加载流程」读完：`core/` 下全部规则、`languages/<目标语言>/` 下全部文件、`references/<目标语言>/gold-dialogues.md`；按 `core/story-structure.md` 先判断用哪种结构（角色主动、主视角被动的走 `core/push-pull-structure.md`）。
1. 按 shortdrama-copy 的规则出 5 个大纲，**直接在对话里展示，不上画布**。大纲只描述人设和剧情，写简短；外语台词每句后面跟中文翻译。展示前逐条过 shortdrama-copy 的「调试与验证」清单和所用结构文件的检查清单，不合格的直接重写。停，等用户在对话里选定或修改。
2. 用户确认（如“用第 3 个”）→ 把确认后的那一个大纲写成文件，`wb put <工程> 大纲 大纲.md`（不加 review，确认已在对话里完成），`wb approve <工程>`。
- 画布只走 CLI（wb），不要靠浏览器去看或操作画布。文字框按内容自动算高度，画布上被改小时 `wb layout` 会改回来。
3. 写全量文案 → `wb put <工程> 全量文案 全量文案.md --review` → 停。通过后进 02。

**02 提示词·音色·3D**（2.5prompt）
- 分幕提示词 → `put … 分幕提示词 提示词.md --review`
- 音色：从用户音色库挑现成音频（`Z:/创新事业部/AIGC项目视频组/设计师物料总库/音频/<地区>音色参考/<性向>/`，例：261111-JP-病娇女教师 用的是 `JP音色参考/男性向/20261016-磁性姐姐-15s.wav`），按角色年龄、性格挑，**不用 TTS 生成**；没法试听就说明是按名字挑的 → `put … 音色参考 <音频> --review`
- 有转头、转身、换场景的镜头就按 2.5prompt 的 3D 参考流程出 3D 视频 → `put … 3D参考 <视频> --review`
- 三样都放上去再停；全部通过后进 03。

**03 人设图**：**必须先加载 Skill `rhtv-character-sheet` 并完整读它的 SKILL.md**，尺度红线、擦边目标、服装改色、质检、积分规则都以它为准（本文件不再重复）。版本数 = 用户给的参考图张数；没有参考图就用文案里写的人设/造型数，再没写用 `defaults.versions_if_unspecified`。每个版本一张：
- 用户给了参考图：按 rhtv-character-sheet 在画布上生成（命令见本文件第六节，`--left` 用上传的参考图节点），自查和独立审核都过了再 `adopt <工程> 人设图 --node <节点> --version N --label <造型> --review`；本地已有合格图就 `put <工程> 人设图 x.png --version N --label <造型> --review`。
- 用户确认后 `approve`；画布清理和删除节点按 rhtv-character-sheet 第六节（删除前要有用户明确指示或同意，并列出要删的节点），画布上只留过审的图。

**04 母版视频**：每个人设图一条。母版视频**永远 480p + 高画质**（`--set resolution=480p --set bitrateMode=high`；用户：「永远只跑480，并且选择高画质」）。
- 每个工程第一次跑母版前，在回复里列一行设置等用户确认：模型、480p、高画质、时长、参考（人设图 / 3D / 音频）、预计积分（报价拿不到就按账单上同设置的实扣估，如 Seedance2.5 28s 480p 高画质 2777 积分）。同设置的后续版本直接跑。
- `wb gen <工程> --type video --prompt-file 提示词.txt --left v<N>·人设图 [--left 3D参考] --set resolution=480p --set bitrateMode=high` → `wb run` → `wb adopt <工程> 母版 --node <节点> --version N --review`。
- 多条母版同时提交：每条 `wb run <工程> --node <节点> --no-wait`，都提交完再一次 `wb wait <工程>`，之后 `wb adopt` 一条条来（第六节第 3 步）。

**05 包装**（mm-packager）：先补全文案（口播、标题、目标、卡片字段）→ `put … 补充文案 补充文案.md --review`；再按版本包装（口播 + 划卡 + 介绍页 + 卡片尾板），母版用 `04_母版/` 里下载好的文件 → 每版 `put <工程> 包装 包装_vN.mp4 --version N --review`。包装和母版生成不冲突，同时做：已经出来的母版先包装，其余版本的母版在平台上跑着，不等全部跑完（用户：「包装和生成视频不冲突」）。

**06 成品交付**：成品、方版、横版只放本地：`wb deliver <工程> --file 成品1.mp4 --file 方版.mp4 …`（更新画布名积分）。用户要求上传投放时再用 xmp-upload。

**07 复盘**：先在对话里按用户每条反馈直接给「哪一步错了、改哪」；需要核对的（翻日志、对文件）放后台补，不开长任务让用户等。依据是本地 `修改记录.md`（通过 / 打回 / 移除都带用户原话，见第四节）。再按各 Skill 的复盘规则列更新点给用户确认。不上画布。

## 六、在画布上跑生成（直接跑，不问用户；母版首跑例外见〇）

1. 选模型：默认用 `wb list` 里的 `defaults`（`image_model` / `video_model`）。要换模型时 `wb rh model search <关键词> --type image|video` 找，再 `wb rh model <MODEL> --type image|video` 读实时 schema；参数只用 schema 里的字段名和取值。
2. 建节点：提示词写进 UTF-8 文件，
   ```
   wb gen <工程> --type image|video --prompt-file <文件> --left v1·人设图 [--left <节点ID>] [--set aspectRatio=16:9] [--model <MODEL>]
   ```
   返回 `node`。节点先放在本行上方的临时区。
3. 运行：`wb run <工程> --node <节点>`。它会先报价、带唯一请求 ID 运行并等结果：
   - `ok:true`：已按报价记账 → 第 4 步。
   - `pending:true`（退出码 4）：还在跑，已按报价记账。用 `wb wait <工程> --node <节点>` 继续等，**不要换 ID 重跑**，也不要先 adopt。
   - `ok:false`：失败，没记账。把 `errorMessage` 和 `code` 原文告诉用户。
   - **多条同时提交**（如 v1–v4 母版）：每条 `wb run <工程> --node <节点> --no-wait`（报价、记账 pending、派发后立刻返回），都提交完再一次 `wb wait <工程>`（不带 `--node`，等这个工程所有 pending 的运行），之后 `wb adopt` 一条条来。同一时间只开一个 `wb run`，不要并行开多个 `wb run` 进程（会把 `画布.json` 账本冲掉）。
4. 收进槽位：`wb adopt <工程> <槽位> --node <节点> --version N [--label 造型] --review`（自动下载到本地对应文件夹）。
5. 没被采用的生成节点用 `wb rh node delete id:<节点> -p <画布ID>` 删掉（画布 ID 在 `wb list` 每个工程的 `canvas_id`）；`wb layout` 的 `orphans` 会列出画布上不属于工作台的节点。

## 七、自定义

列宽、间距、行距等：在 `~/.rhtv-workbench/config.json` 加 `"layout": {...}`（键同 wb.py 的 LAYOUT），然后 `wb layout`。默认模型、默认版本数改 `"defaults"`。测试时用过 `--prefix 测试-` 的，正式使用前 `wb setup --designer … --root … --prefix ""` 清掉（list/check 会提醒）。

## 八、注意

- 不在 RHTV 上的花费（ElevenLabs、本地渲染）不计入画布积分。
- 跨平台：Windows 已验证；macOS/Linux 需要先按 rhTV 官方 USAGE.md 安装客户端，wb.py 会自动找 `~/.runninghub-canvas`。
