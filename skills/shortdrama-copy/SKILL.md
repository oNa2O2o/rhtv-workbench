# 多语言短剧台词本地化

将中文剧情、角色图或零散台词，改写成适合韩国/日本/欧美市场的短剧文案，输出对照表格，包含标题、分幕、表演指示、台词、UI选项、数值变化和结尾卡。

---

## 语言检测与路由

### 自动检测规则

**优先级1：显式指定**
```
/kr, /korean, 韩语, 韩国市场
/jp, /japanese, 日语, 日本市场  
/en, /english, 英语, 英文, 欧美市场
```

**优先级2：关键词判断**
- **韩语触发词**：韩语台词, 韩中对照, MiraiMind에서, 한국어
- **日语触发词**：日语台词, 日中对照, セリフ, ローカライズ, 日本語
- **英语触发词**：English dialogue, EN localization, English script

**优先级3：默认规则**
- 中文输入 → 默认韩语
- 英文输入 → 默认英语
- 日文输入 → 默认日语

### 加载流程

```
1. 检测目标语言
   ↓
2. 加载共享规则（core/）
```

## 核心质量原则（全语言通用）

### 1. 本地化优于翻译

**优先级：**
```
目标语言的母语者自然会说的话 > 符合角色身份 > 保留中文原意 > 字面对应
```

**示例：**
- 韩语："狐狸精" → `여우 같은 애`（心机女）
- 日语："狐狸精" → `小悪魔`（魅惑型女性）
- 英语："狐狸精" → `homewrecker`（破坏家庭的女人）

### 2. 台词必须短

- 一行只表达一个情绪或信息点
- 删除解释性连接词
- 同一角色连续台词要有情绪递进
- 一幕约10s时只写2句台词，道歉、客套、赶人这类功能句改成动作交代

**长度限制：**
- 韩语/日语：每句≤20字中文
- 英语：每句≤15词
- 所有语言：每幕≤3句台词

### 3. 文化差异主动替换

遇到文化专属概念时，按剧情功能替换：

| 场景 | 韩语 | 日语 | 英语 |
|---|---|---|---|
| 心机女 | `여우 같은 애` | `ぶりっ子` | `fake innocent girl` |
| 职场上司 | `부장님`（敬语） | `部長`（敬语） | `Director` |
| 偷拍 | `몰카` | `盗撮` | `creepshot` |

### 4. 产品名称与标题

- 出现产品名时统一使用 **MiraiMind**（禁止缩写为 MM）
- 标题**不强制**套「在MiraiMind中 + 动作」模板；默认写网感信息流短句（如「交不起房租是你的谎言」），详见 `core/title-endcard.md`
- 标题、结尾卡先给多个候选让用户选

### 5. 台词必须像真人说话

- 先想这个场景里真人会怎么说，禁止书面腔、刻意修辞、旁白式台词（❌「会冻伤的哦，冻伤的是你」）
- 人外/特殊设定放进表演指示画面和双关里，不在台词里说教

### 6. 人设与调研

- 有角色参考图必须按图写服装和特征，不按刻板印象套（守寡3年≠穿丧服）
- 特定角色、本子角色、人外题材先调研设定与受众语境；无法联网要如实说明
- 参考竞品素材要看原片画面，只拿到文字描述时要说明
- 用户限制服装尺度时只调长度和尺度，保留角色的标志性服装
- 写全文前先给5个剧情大纲让用户选方向
- 高傲、冷淡型角色破防时用别开视线、重新摆架势这类克制小动作表现，不写脸红、耳朵红和夸张惊讶

### 7. 画面可执行

- 不写需要额外道具交互的动作（递衣服、披外套、遗照特写）；场景尽量≤2个
- 持武器威胁写成警告动作（比「嘘」、敲地、横在身前），武器不碰到主视角
- 角色的处境（被追捕、被监视等）用画外音或环境声交代，不让角色自己说出来

### 8. 选项与屏幕文字

- 视频里被选中/被点击的选项，必须和下一段画面剧情接得上
- 自己觉得别扭的句子直接重写再交付，不把「建议删或换」留给用户
- 每幕最后一句把话抛给主视角（问句或欲言又止），选项写成主视角对这句的回答原话
- 最后一题的选项可以都只说一半，不点选，把答案留到下载之后
- 开场字写画面演不出来的设定或规则，不复述画面
- 卡片标题不剧透剧中要揭晓的身份
- 结尾卡可以用短问句把选择抛给观众
- 选项里提到的东西，前面画面里必须先出现过，且全片叫法统一

### 9. 剧情推进

- 三幕情绪要有起有落，不能一路平铺或单向递增，最后一幕必须是情绪最高点
- 角色态度的每次变化都要有画面里的事件当动机，陌生或敌对关系不凭空给好感
- 每一幕都要让关系或真相发生实质变化，不能三幕重复同一种态度
- 前面幕里的台词或动作，后面要回收成伏笔或反转的依据（所有结构通用）
- 第三幕的真心话要在嘴硬否认时说漏，并且说到一半就被打断，把答案留到下载之后
- 开场第一句就要有信息或笑点，不用纯拟声或无意义的台词垫场
- 能用一声短喊或拟声表达的情绪，就不写成解释句
- 角色的口癖、自称和对主视角的称呼一旦定下来，全片统一贯穿，不要因为怕刻意就减少
- 换场景或关系跳一步时，写一句转场字交代心理变化，不硬切
- 角色嘴上拒绝的东西，后面安排主视角撞见她偷偷接受，作为态度反转的证据

### 10. 转化段 / 口播

- 口播、片尾、标题先从 `references/投放高效文案.md` 按地区和性向取达标文案，改写只换屏蔽词和角色名
- 转化段口播先讲产品卖点，再讲角色或剧情，每段一句
- 口播做概括，不复读画面上已有的台词或气泡，一句口播可以横跨相邻几个画面

## 核心输出规则

1. **中文栏 = 【表演指示】单独行 + 中文台词**（中文台词是目标语言的对照翻译，不能省略）
2. **目标语言栏 = 纯台词翻译**（表演指示处留空行，不写表演指示，不写幕名）
3. **敏感词和谐**：动词用 ◯◯ 替代（至少两个圆圈）；「前任」类称呼（前男友 / 元カレ / ex）和「女友」类称呼（女朋友 / 彼女 / girlfriend / 여자친구）属违规词，前任改用中性代称（他 / 彼 / him），女友改用具体关系（青梅竹马 / 幼馴染 / 同学 / 邻居等）
4. **每幕标注数值**：数值名称开始确定后三幕不可更改，只改变数字体现角色变化；每次变化标出由哪个选项、哪句台词或哪个画面事件引起，不按幕平均递增
5. **结尾卡分两行**：陈述 + 下载引导

### 默认值

- 每幕台词默认2句，上限3句
- 屏幕字幕去掉句尾「。」，保留「？」「！」「…」
- 上升型数值（心动、好感）结尾停在 99，不打满
- 正片默认不写口播，也不额外加反转；包装转化段默认写口播：产品一句、剧情一句、片尾一句
- 数值名贴合角色当时的处境（危险/陌生关系用警戒度、渴求度），不默认用好感度
- 默认只设一个数值
- 数值单次变化 30–50；出现外部威胁时数值要反弹一次

## 语言特定规则

### 韩语（Korean）

**完整规则参考：** `languages/korean/`

**核心特征：**
- 敬语/半语系统：`-요/-습니다`（敬语）vs `-어/-야`（半语）
- 职场上下级称谓：`부장님`, `과장님`（必须带敬语）
- 网络俚语：`몰카`（偷拍）, `오버`（过分）
- UI提问标记：`【UI 질문】`
- 下载引导：`다운로드하고 다음 내용 보기`

### 日语（Japanese）

**完整规则参考：** `languages/japanese/`

**核心特征：**
- 敬语系统：`です・ます体`（礼貌）、`だ・である体`（常体）、尊敬语、谦逊语
- 人称代词：男性自称（`俺/僕/私`）、女性自称（`あたし/私`）
- 语气特征：强势女性（`〜わよ`）、可爱型（`〜だよ`）、大小姐（`〜ですわ`）
- 方言变体：关西腔（`〜やん`）、博多腔等
- UI提问标记：`【UI質問】`
- 下载引导：`ダウンロードして続きを見る`

### 英语（English）

**完整规则参考：** `languages/english/`

**核心特征：**
- 语气层级：Formal（正式）、Casual（随意）、Intimate（亲密）、Aggressive（攻击性）
- 俚语与缩写：`gonna`, `wanna`, `kinda`
- 强调词：`literally`, `totally`, `absolutely`
- 短句打断："What?" "Seriously?" "No way."
- UI提问标记：`【UI Question】`
- 下载引导：`Download to see what happens next`

## FAQ

### Q1：如何显式指定语言？
**A**：在请求中添加 `/kr`, `/jp`, `/en` 或明确说"韩语短剧"、"日语短剧"、"英语短剧"。

### Q2：不指定语言会发生什么？
**A**：自动检测。中文输入默认韩语，英文输入默认英语，日文输入默认日语。

### Q3：可以混用多种语言吗？
**A**：一次只能生成一种目标语言的对照表格。如需多语言版本，请分别调用。

### Q4：如何切换语言？
**A**：在新请求中显式指定目标语言即可，skill会自动切换路由。

### Q5：旧的韩语案例还能用吗？
**A**：完全兼容。所有韩语相关功能保持不变，案例已迁移到 `references/korean/`。

## 调试与验证

**检查当前语言设置：**
- 询问"当前目标语言是什么？"
- skill应回答：韩语/日语/英语，并说明检测依据

**验证输出质量：**
- 台词长度是否符合限制？
- 语法/语气是否符合目标语言母语者习惯？
- 文化适配是否到位？（职场称谓、俚语、禁忌词）
- 用户给的原文/参考台词已校语法和错字，改动处已标出？
- 三幕情绪曲线有没有起落？第三幕是不是最高点？
- 每一幕主线有没有往前推进？
- 第三幕有没有说到一半被打断的钩子？
- 口癖、自称、称呼是否全片统一？
- 每幕最后一句有没有把话抛给主视角？
- 没有提问，只靠前一幕末句选项能不能看懂？
- 角色态度的每次变化有没有画面动机？
- 有没有加用户没要的元素？
- 开场字是不是只复述了画面？
- 卡片标题有没有剧透身份？
- 每次数值变化有没有对应的选项或台词？
- 换场景的地方有没有转场字？
- 选项里的东西前面出现过吗？叫法统一吗？
- 表演指示的表情幅度符合人设吗？
- 武器有没有碰到主视角？
- 数值有没有至少一次反弹？

**切换语言测试：**
- 同一剧情分别生成韩/日/英三个版本
- 对比核心结构是否一致
- 对比本地化细节是否准确
